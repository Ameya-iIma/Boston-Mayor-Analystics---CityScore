# Boston CityScore: State of City Services

## Project Link
[View Live Dashboard](https://boston-mayor-analytics-city-score-p8ouive2d.vercel.app/dashboard)

MBA analytics consulting project for the Mayor of Boston. This project turns the CityScore datasets into a mayor-ready executive dashboard and backend pipeline that answer three questions for each service:

- Are we meeting the goal?
- Are we getting better or worse?
- Does this need action today?

## Project Scope

The solution uses the four provided CityScore source files and organizes them into a backend pipeline that performs:

- ingestion of daily source files
- cleaning and standardization
- metric-level and city-level aggregation
- executive classification and alerts
- API delivery for the dashboard

The frontend then presents the output as a mayor briefing rather than a technical analytics console.

## System Overview

### Backend

The FastAPI backend serves:

- pipeline refresh and status endpoints
- executive brief endpoints
- city history and alert endpoints
- service area summaries
- metric lists and drill-down detail

Core outputs generated by the pipeline:

- `metric_master.csv`
- `metric_history_long.csv`
- `city_score_history.csv`
- `latest_metric_snapshot.csv`
- `mayor_alerts.csv`
- `service_area_summary.csv`
- `executive_brief.json`

### Frontend

The dashboard is designed as a mayor-ready briefing with:

- executive diagnosis
- interpretation and scope panel
- portfolio mix classification
- top 5 and bottom 5 service rankings
- leadership actions
- methodology
- citywide trajectory cards
- alerts, service-area summaries, and metric drill-downs

```bash

```

Then open:

```text
http://127.0.0.1:8000/dashboard
```

## Key Design Rules Used In The Dashboard

- CityScore `> 1` means above target
- CityScore `< 1` means below target
- Best performers are not ranked from one snapshot alone
- Worst performers combine current gap, trend, consistency, and severity
- Missing data is treated separately from poor performance
